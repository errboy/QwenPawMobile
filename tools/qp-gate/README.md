# qp-gate — QwenPaw 局域网守门代理

让局域网里的手机连上**只绑回环**的 QwenPaw 桌面端后端。**桌面端零改动、手机端零改动**：
后端继续听 `127.0.0.1:<随机端口>`，本工具听 `0.0.0.0:61700`，中间这一层由它守。

## 为什么需要它

QwenPaw 桌面版（Tauri GUI 启动）硬编码只绑 `127.0.0.1`，手机直连不到。改 `entry.py`
的办法在**安装版**上无效——安装版是 PyInstaller 编译包，仓库源码改了不影响它；而且
桌面端一升级，改动就没了。所以把能力放在外面这个独立小工具里：它只依赖公开的
HTTP 接口，桌面端升级不会让它失效。

## 为什么门禁必须做在这里（重要）

转发到后端时源地址是 `127.0.0.1`，而 QwenPaw 的鉴权按**客户端 IP** 免检
（`security.allow_no_auth_hosts` 默认含回环）。也就是说在这个拓扑下后端那一层鉴权
**根本不参与**。"让桌面端开鉴权 + 代理只做转发"是假安全：代理自己就是那个免检的回环
客户端。所以本工具亲自实现鉴权面，其余路由一律带令牌才转发。

同理，**别用 `netsh interface portproxy`** 做转发：它会把来源伪装成 `127.0.0.1`，
等于把鉴权也一起绕掉。

## 快速开始（Windows）

`start.bat` 是唯一入口，它自己会找一个可用的 Python 3：

```bat
start.bat                  : 启动。gate.json 不存在时先引导设置账号、口令与放行网段
start.bat stop             : 停掉正在监听的那一个（只停它认得出是自己的进程）
start.bat config           : 改配置：登录用户与口令（可跳过）、两个端口、放行网段
start.bat password         : 只换手机端登录的用户名与口令
start.bat discover         : 只看探测到的上游端口，然后退出
start.bat show             : 打印当前生效配置，连每一项的含义一起打
start.bat check            : 跑一遍自检（自带桩上游，不碰真实配置）
start.bat firewall         : 单独添加 Windows 入站放行（会弹 UAC）
start.bat firewall-remove  : 删掉本工具加的防火墙规则
start.bat help             : 列出上面的命令
```

## 用完就停

它听的是 `0.0.0.0:61700`：局域网里任何知道这个地址的人都能摸到桌面端，中间只隔一个
登录口令。所以**不用就关掉**，别让它常驻——这是整套门禁里最便宜的一条保护。

- 停止：窗口还开着就在那个 cmd 里按 `Ctrl+C`。**"窗口没了"不等于"进程没了"**——它被后台
  或脚本拉起来的时候根本没有窗口，真实踩过一次，一整夜没人发现。那一种用一条命令收：

  ```bat
  start.bat stop
  ```

  它去系统的连接表里找正在 `LISTENING` 配置端口的那个进程，**只停命令行里带着 `qp_gate`
  的那一个**，杀完再回头看一次连接表才敢说停了（端口从 `gate.json` 读，所以你自己改过端口
  它照样找得着）。撞上同一个端口的别的服务它拒绝动手，只把那个 PID 和它的命令行打给你看——
  这时它返回失败，而不是"已停止"。
- 想自己核一眼（`--stop` 拒绝动的那个进程、或者你想确认防火墙之外的东西）：

  ```bat
  netstat -ano | findstr :61700
  ```

  只剩 `TIME_WAIT` 行是内核在收尾，不是监听；出现 `LISTENING` 才是还在跑，把那行最后一
  列的 PID 用 `taskkill /PID <pid> /F` 停掉。
- 停掉**不删**防火墙规则，也**不作废**手机上已签发的令牌（`token_secret` 存在 `gate.json`
  里，只有 `--init --force` 才会重生成）。下次 `start.bat` 一拉，手机直接就能连上。

## 配置：三层入口，日常只碰第一层

| 想做的事 | 用什么 |
|---|---|
| 改登录口令 / 换端口 / 改放行网段 | `start.bat config` |
| 只换口令 | `start.bat password` |
| 改完想确认生效值 | `start.bat show` |
| 改其它字段（令牌有效期、连接上限、限流窗口、监听地址） | 手改 `gate.json`，再 `start.bat show` 复核 |

`start.bat config`（等价于 `python qp_gate.py --edit`）**每一项都把当前值当默认**，
一路回车等于什么都没改；口令问一次、答 `n` 就跳过。它和首启的 `--init` 有一条要紧的
区别：`--edit` **不重新生成 `token_secret`**，所以改端口不会把手机上已签发的令牌作废、
不会把人莫名登出。**别拿 `--init --force` 当"改配置"用**——它会重生成 `token_secret`，
`--init` 撞上已有的 `gate.json` 默认拒绝覆盖也是这个原因。

## 两个端口分别是什么

- **`listen_port`（对外的端口，手机里填的就是它）**：守门代理在 `0.0.0.0` 上听的端口。
  推荐值 `61700`，只有被别的程序占了才需要换；`--edit` 里可以直接输自定义值。换过端口
  之后它会接着补 Windows 入站规则（旧规则只放行旧端口，不补的话手机端只会超时），
  这一步要你在 UAC 弹窗里批准。手机端登录配置页把扫描端口填成同一个数字。
- **`upstream_port`（桌面端在回环上听的端口）**：默认填 `0`，意思是**自动发现**。
  桌面端每次重启都会换一个随机端口，所以这个值根本不该写死：发现流程先读
  `~/.qwenpaw/config.json` 里记的 `last_api.port`，再兜底扫本机回环监听表，每个候选都
  要用 `/api/auth/status` 的真实响应形状确认才算命中（命中后缓存 15 秒，转发失败立刻
  重探）。**自动发现就是这里的最佳默认**，日常不用管它。
  只有两种情况才钉死：你确实给桌面端指定过固定端口，或者自动发现总是找不到它。钉死之后
  桌面端一换端口就连不上，症状是"手机连上网关但拿不到回复"，看起来像网关坏了——所以
  想改回去在 `--edit` 里输 `0` 或 `-` 就行。

`--edit` 问的只有这四件事（口令、`listen_port`、`upstream_port`、`allow_cidrs`）；
`token_ttl_seconds`、`max_connections`、`login_max_failures`、`login_window_seconds`、
`listen_host`、`upstream_host` 属于高级项，手改 JSON。改法与含义在 `gate.example.json`
的 `_comment_*` 键里，运行时也可以用 `start.bat show` 直接看。

`--init`（和 `--edit` 的最后一问）会探测本机在局域网上的 IPv4（只问内核要路由出口，一个
包都不发），把每个地址所在的 /24 作为建议值打出来，回车采用、改写成别的、或者输 `-`
表示不限网段。探测不到（没联网、只有回环）就默认留空并告警——留空是**能连上**的那个
选项，填错网段是连不上。`--edit` 里回车拿的是**当前已配置的网段**，不是这一刻探测到的
网卡：插着 VPN 时改个端口，不该顺手把网段换掉。

想演练一遍首启又不碰真实配置，给任意一条命令带 `--config <临时路径>`：

```bat
python qp_gate.py --config "%TEMP%\qp-gate-drill.json" --init
```

演练用的配置**不会动 Windows 防火墙规则**（`--init`、`--edit`、启动都按配置文件是不是
默认的 `gate.json` 来决定要不要提权改系统）：否则照着上面这条敲一次，机器上就多一条
针对临时端口的永久放行，而且没人会想起来删。

口令**只在提示符下输入**，从不作为命令行参数：参数会留在进程列表和 shell 历史里，
局域网上的这台机器不该冒这个险。

或手工（与上面的子命令等价）：

```bat
python qp_gate.py --init              :: 首启：用户名 + 口令 + 放行网段，并放行防火墙
python qp_gate.py                     :: 启动
python qp_gate.py --stop              :: 停掉正在监听的那一个（只停命令行里带 qp_gate 的）
python qp_gate.py --edit              :: 日常改配置：口令（可跳过）、两个端口、放行网段
python qp_gate.py --show              :: 打印生效配置连每一项的含义
python qp_gate.py --discover          :: 只看探测到的上游端口
python qp_gate.py --set-password      :: 换口令（口令只走交互输入，不做命令行参数）
python qp_gate.py --remove-firewall   :: 删掉本工具加的防火墙规则
```

手机端：登录配置页把扫描端口填 `61700`，扫描后点选这台机器，用户名/口令填 `--init`
里设的那两个，登录。要填的完整地址不用自己拼——启动横幅和 `start.bat show` 都会把
`http://<本机局域网地址>:61700` 逐条打出来，多网卡就逐条列，自己挑和手机同网段的那一个。

## 快速开始（Linux / macOS）

没有 `start.bat`，直接跑同一个脚本；行为、配置、自检完全一致：

```bash
python3 qp_gate.py --config /tmp/qp-gate-drill.json --init   # 先演练一遍（可选）
python3 qp_gate.py --init
python3 qp_gate.py                       # 启动；非 Windows 下只提示你自行放行
python3 qp_gate.py --edit                # 日常改配置：回车保持原样
python3 qp_gate.py --show                # 手机要填的地址 + 每一项含义
python3 qp_gate.py --stop                # 停掉正在监听的那一个（同样只停认得出是自己的）
python3 qp_gate.py --config /tmp/qp-gate-drill.json          # 用临时配置起一个对照实例
```

防火墙这一层本工具不代劳（`netsh` 是 Windows 独有的）：自己放行 TCP `61700`，
`sudo ufw allow 61700/tcp` 或 firewalld 的 `--add-port=61700/tcp`。已经有反代或不想
放行时启动带 `--no-firewall`，它就不提这件事。

后台运行与开机自启交给 systemd 用户服务或 `launchd`，本工具不写系统配置：进程只监听
一个 TCP 端口、无状态，令牌与口令散列都在 `gate.json` 里，重启不需要恢复任何东西。

## 它做了什么

| 路由 | 行为 |
|---|---|
| `GET /api/auth/status` | 本地应答 `{"enabled": true, "has_users": true}`。客户端 `AppStore.signIn` 见到 `enabled=false` 会**直接跳过登录**存空令牌，所以这一行是登录能发生的前提 |
| `POST /api/auth/login` | 校验 PBKDF2 口令，签发本工具自己的 HMAC 令牌 |
| `POST /api/auth/register`、`/update-profile`、`/revoke-*` | **403**，只留给本机桌面端用：局域网里任何访客都不该能在别人机器上建管理员 |
| 其他全部 `/api/*` | 必须带 `Authorization: Bearer <令牌>`，否则 401；带上了就原字节转发给回环后端 |

转发是 **TCP 层逐字节搬运**，只把请求头的 `Connection` 改成 `close`（否则上游会等下一个
请求、拿不到 EOF，普通请求会挂成超时）。因此 SSE 不断流、54MB 附件不聚合进内存、二进制
预览逐字节一致——这三条都有自检兜着。

上游端口默认是**自动发现**的，桌面端重启换端口不用改配置（细节见上面「两个端口分别是
什么」）。发现过程的探测在独立线程里并发跑，不会卡住正在推的 SSE。

## 安全边界

- 口令只存 `pbkdf2_sha256$迭代数$盐$散列`（20 万次迭代），明文不落盘、不进命令行、不进日志。
- 令牌是本工具自签的 HMAC-SHA256，默认**永久**（`token_ttl_seconds: 0`）。手机端没有
  401 自动重登逻辑（`core/Failure.ets:44` 只把 401 归成 Unauthorized 报错），所以令牌
  一过期用户就只看到报错，别把这里改成有限值除非你打算顺手加手机端的续期。
- `gate.json` 已被 `.gitignore` 排除——**不要提交它**。非 Windows 下写盘后 `chmod 600`；
  Windows 上 `os.chmod` 只动得了只读位，真正的权限由所在目录的 ACL 决定，所以别把
  `gate.json` 放进共享目录或网盘同步目录。
- `allow_cidrs` 由 `--init` 探测本机网段后让你确认（见「快速开始」）：不在名单里的地址
  连 `/api/auth/status` 都摸不到。留空表示不限网段（仍有口令限流），启动时会告警。
  被拒时守门代理**会**在日志里打出被拒的 IP 和当前生效的网段——手机不知道自己局域网地址，
  没有这行就没法往下走。
- 登录按 IP 限流：默认 60 秒内 8 次失败后返回 429，窗口内即使口令正确也拒。
- 畸形请求、绝对形式请求行、`CONNECT` 隧道、超长请求头都会被拒，且单个坏请求不会让守门
  进程退出。

## 自检

```bat
python selftest.py
```

自带桩上游，不依赖桌面端，也不碰你真实的 `~/.qwenpaw`；**改完 `qp_gate.py` 必跑**，跑一遍会把
每一项打出来。它兜的是这些：鉴权面接管与不泄漏、口令错误与限流、伪造 / 过期 / 无令牌三种转发、
`Connection` 改写与 X-Forwarded-For、SSE 分帧的到达时间、8 MB 请求体与二进制逐字节一致、畸形请求
与 `CONNECT` 隧道拒绝、网段白名单（拒绝必须在日志里点出被拒地址）、上游端口发现、本机地址探测与
横幅回声（不许打 `0.0.0.0` 这种填不进手机的地址）、日常改配置（一路回车必须一个字都不改、改端口
不许作废令牌）、防火墙放行是否真的落地（**拉起提权进程不等于放行成功**）、`--stop` 的认领与停实
（端口上坐着陌生进程时必须拒绝动手，那个进程还得原地活着）。

## 已知边界

- 只做 HTTP，不做 HTTPS。令牌在局域网里是明文传输的——和桌面端自己的 `/api/console/*`
  一样的暴露面。跨机敏感场景请自己上反代 TLS。
- 要求令牌就意味着：**加不上 `Authorization` 头的消费方取不到媒体**。手机端是把媒体字节
  自己带令牌取进沙箱、再按 `file://` 播放的（`net/ApiClient.ets`），所以经网关播放没问题；
  但把 `/files/preview` 的 URL 直接粘进浏览器地址栏、或交给一个不能自定义请求头的播放器，
  拿到的会是 401。
- 只放行 `/api` 前缀之外的路由没有意义：客户端所有请求都走 `{server}/api{path}`，非
  `/api` 的路径同样要求令牌。

还欠一件事没验：`--edit` / `start.bat config` 的**人机手感**——在真人的命令行窗口里一路敲下来
是什么体验。逻辑与边界由 `selftest.py` 兜着，但脚本喂答案不等于人敲键盘。
