# 09 · 排障

先分清是哪一层：`手机上没反应` 可能是 App、网关、桌面端、网络四者之一。
按下面顺序二分，比读代码快。

## 1. 构建期

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `hvigor ERROR 00303116: storePassword ... less than 32` | 签名占位是空串而 `external-signing-config.json` 不存在 | 现版 `hvigorfile.ts` 已修：没材料就丢掉 `signingConfigs` 出 unsigned hap。若仍出现，说明 `build-profile.json5` 被改回带空口令的配置 |
| 构建报非法资源路径 / 把某目录当成资源 | 备份图片放进了 `resources/**` 子目录 | 素材备份必须放在 `resources` **之外**（hvigor 资源扫描器不接受资源目录里的子目录） |
| 只改了 `.ets` 但 `--apply` 不生效 | 改动含资源/`module.json5`/`@State` 装饰器本身 | 全量 `devecocli run`，别用 `--apply`/`--skip-build` |
| ArkTS 检查报错但 IDE 里"看着没问题" | ArkTS 比 TS 严：禁 `any`、对象字面量需形状 | 按报错行号改；`devecocli check arkts --fix` 先补高置信度问题 |

## 2. 装机与启动

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `Error Code:10106102 ... device screen is locked` | 包已装上，启动被锁屏挡住 | 唤醒 + 上滑解锁：见 [03](03-run-on-device.md) §2 |
| 装机失败、提示签名不一致 | 换过证书 | `devecocli run --device <序列号> --uninstall` |
| `Smoke: FAIL_BLANK` | 首屏白 | 看输出里 `screenshot:` 指向的图，再 `devecocli log --crash` |
| 一条 INFO 日志都没有 | user 版系统裁 INFO | `devecocli log --level W --bundle-name com.liaocaosix.qwenpawmobile` |
| 命令报"多设备" | 同时连了真机和模拟器 | 所有设备类命令显式 `--device <序列号>` |

## 3. 连接（最常见的一层）

**先确定测的是谁**：真桌面端还是桩。mock 通过不代表联调通过。

| 现象 | 最可能的原因 | 怎么确认 |
| --- | --- | --- |
| 扫描列表空的 | 网关/桌面端没在跑；端口不对（扫描默认 8088，qp-gate 是 61700）；手机不在同网段 | 电脑浏览器打开 `http://127.0.0.1:<端口>/api/auth/status`，有 JSON 说明后端活着 |
| 扫描到的地址连不上 | 扫的是网关的另一个口，或防火墙拦了 61700 | `python tools/qp-gate/qp_gate.py --init` 会放行防火墙；手工核对 Windows 防火墙入站规则 |
| 模拟器怎么都连不上宿主 | 用了 `127.0.0.1` 或宿主机局域网 IP | 模拟器访问宿主用 `10.0.2.2`；且**不要指望局域网扫描**——它扫的是 `10.0.2.x` |
| 登录后立刻 401 | 令牌被网关拒（口令换过、`allow_cidrs` 变了） | 手机没有 401 自动重登（`core/Failure.ets:44` 只把 401 归成 `Unauthorized`，不重新换令牌），重新登录一次；仍失败就 `python tools/qp-gate/selftest.py` 验网关 |
| 登录页红字是 `登录失败：HTTP 502 /auth/login` 这一类 | 电脑端或网关回了非鉴权类的错（5xx 多为网关在上游已死时兜底）。`登录失败：` 后面的 `HTTP <码> <路径>` 是**给你抄去问人的**，不是 App 自己坏了；只有 `用户名或密码错误` 和 `尝试过于频繁，账号暂时锁定` 两支是登录页自己认得的码 |
| 网关启动报端口被占 | 已经有一个实例在跑 | 先看进程，不要改端口——两个网关会抢上游发现。`qp-gate` 拒绝回环地址接入，这是设计 |
| 流式回复卡住不结束 | 中间有代理改了/吞了 `Connection` 头，或做了响应缓冲 | qp-gate 只在 TCP 层逐字节搬运并改写 `Connection: close`；换成别的转发方式就要自己验 SSE 分帧 |
| 图片能看，视频放不出来 | `Video` 组件加不上 `Authorization` 头 | 已知边界（`tools/qp-gate/README.md`）。要么该路径可匿名访问，要么接受看不了 |
| 上传失败 | 超过 `GET /api/settings/upload-limit` | 手机端按这个上限先拦，别改服务端配置 |
| 手机端什么都是 403 | 后端开了鉴权但手机走的是"跳过登录"分支 | `GET /api/auth/status` 必须回 `enabled: true`；qp-gate 自演这一面正是为此 |
| 首页横幅说「无法连接服务器」，可电脑端明明活着 | 服务器**答了**，只是答的东西不是列表（200 回一个对象而不是数组）。这两种故障在横幅上长得一样，分开它们只看日志：`devecocli log --level W` 里应有一句 `轮询失败：<端点> 返回的不是一份列表`。有 → 后端那个端点的响应形状变了，拿 `curl -H "Authorization: Bearer …" http://127.0.0.1:<端口>/api/chats` 直接看它回了什么；没有 → 是连不上，回到上面几行 |
| 打完字点发送，气泡闪一下就没了，屏幕上没说失败 | **这一版之前**的行为：那条 POST 被服务器拒了（409/429/5xx），而随后的历史重建把乐观气泡当成"已送达"丢掉。现在那条会留着并标红字「未送达」+ 一句「这条没有发到服务器，长按它可以引用重发」。**长按引用只在这一次停留期间有效**：退出会话再进来，服务器没有它、手机上那份也一起没了 |

## 4. 布局

| 现象 | 原因 |
| --- | --- |
| 平板/折叠屏上正文横贯整屏 | 没走 `AppMeasure.text/panel`，直接写了 `100%`（见 [06](06-responsive-devices.md) §3） |

## 5. 多媒体播放

| 现象 | 原因 |
| --- | --- |
| 视频气泡上写"视频暂不支持播放" | 这句是 **`Video` 组件自己盖的**，不是本 App 的文案（我们那条是"视频暂不可用"）。原因是容器解不开：测试用假 mp4（只有 `ftyp`、没有 `moov`）必然如此，用 ffmpeg 真造一条再判 |
| 语音报 `unsupport prepare operation` | `AVPlayer` 的 `prepare()` 只能在 `initialized` 状态调，而该状态是赋值 `url` 之后**异步**上报的。见 `media/AudioPlayer.ets` 头部注释 |
| 气泡一直停在"播放中" | 播放失败没回传。`play()` 不 reject，失败一律走 `onFail` 回调并复原标记 |
| 换了真素材仍放不出旧 clip | `cacheDir/media` 里那份是按"服务器地址 + 引用路径"哈希命名的旧字节，命中即不再下载（换服务器地址会自动重取，同一台电脑上换文件不会）。主页那行「清理」→ 勾 `看过的视频` / `听过的音频` → 确认，再看 |
| 清理后第一次播放明显慢一点 | 字节要重新取回再落盘。`pathFor()` 每次调用都重新确认文件在不在，所以不会拿被删掉的缓存去播 |
| 视频气泡停在 00:00 放不动，退出这个会话再进来就好了 | 手机上的那份缓存被系统收回了，而气泡里那个 `file://` 地址是进会话时算好的。`cacheDir` 本来就归系统管（模拟器实测几十秒就收一次，真机待验），重进会话会按 `pathFor()` 重新取一次字节。资产面板那一行也会跟着回落到「仅电脑端」 |
| 录完停止时提示"录音是空的，没有附上文件" | 采集一帧都没进：take 落盘只有 258 字节的空 `mdat` 骨架，被 `SILENT_TAKE_BYTES` 判空丢弃。**模拟器 + 宿主机没有麦克风输入设备**时必然如此（guest 侧 hilog 每 1 秒一条 `audioCapturer Read() fail`；宿主机可用 `Get-CimInstance Win32_PnPEntity -Filter "PNPClass='MEDIA'"` 看，列表里只有输出、没有输入端点就是这台机器的情况）。这不是代码缺陷 —— 要看出声效果，换真机（用手机自己的麦克风）或先给电脑接一个输入设备 |
| 电脑端消息里提到的图片/视频在手机上不显示，`📁` 也不数它 | 先分清是哪一种"提到"。① content part 的 ref 是 `file:///…`（电脑那台机器的磁盘路径），手机取不到，按 [07](07-server-contract.md) §8.3 不建媒体节点、不进面板 —— 但 `[图片]` 标签和文件名仍留着，那条消息本身没被藏起来。② 工具卡的**正文文字**里写了一个路径，那只是那句话，app 不拿正文当地址去取。③ 电脑端**真的把文件发过来**（发文件工具，形状是 `output` 里那份块列表）—— 这一种现在会显示：文件在卡片上方各占一行，卡片照常进资产面板。若这一种仍然只剩一句话，那是解析坏了，见 [05](05-architecture.md)「电脑端「发文件」住在工具卡的 output 里」。和上面 00:00 那行不是一回事：那一行的 `file://` 是**手机自己沙箱**里缓存字节的地址，那个能播 |
| 电脑端发来的文件那一行写「内嵌文件」，而且没有「查看」 | 那一份是工具**内联**在消息里的字节（`source.type` 为 `base64`）。真实历史里这种块**可以完全没有 `name`**（同一批数据里带名字的与不带名字的都有，所以只能按形状分派，不能猜），屏幕于是给一个类别名、大小按 base64 长度折算；不给「查看」是因为那些字节虽然随消息到了本机，却没有任何引用能让缓存去取它、也没有容器后缀让系统阅读器认住它。旧版本在这里显示的是从 `data:…;base64,…` 尾部切出来的一串乱码当文件名 —— 再看到那一串就说明 `PartTemplates.inlineFile` 的接线断了（`state/ChatStore.ets:51`）。见 [05](05-architecture.md)「电脑端「发文件」住在工具卡的 output 里」 |
| 点「查看 ›」什么也没发生 | 三种可能，都还在设计之内：① 那一行正写着「正在取字节…」，字节要从电脑端取，这期间再点**不会起第二个 fetch**（等它变回 `查看 ›`）；② 这台手机上没有能读这个后缀的应用 —— 会给一句「这台手机上没有能打开它的已装应用」；③ 系统那道「"QwenPaw"想要打开…」的确认被点了`取消`，那本来就不该打开任何东西 |
| 外部应用起来了却说「原始文件已被移动或删除」之类 | 它拿到的那份字节**不在或为空**：要么缓存被系统收回了（同上面 00:00 那条），要么交接前那一步类型查询就失败了、`startAbility` 压根没带上文件。两种都不是外部应用坏了 —— 退出会话再点一次 `查看 ›` 会重新取一次字节 |
| 自己发出去的图/视频在手机上还在，电脑端同一轮却只有一句话 | 服务端只给带 `file_url` 的 `file` 分片另存原始内容，媒体轮的原文它没存，回给两边的是模型侧那句"用户上传文件，已经下载到 …"（[07](07-server-contract.md) §8.1）。手机上那份是**本机回显**（`state/ChatStore.applySentMedia()`），两端不一致是服务端事实，不是手机把内容改了 |

## 6. Windows 上的脚本

- `.bat` 必须是 **CRLF + 纯 ASCII**。用带 LF 或中文的工具写 `.bat`，`cmd` 会把整段炸掉（本机 ACP=936）。
- `.ps1` 里带中文必须存成 **UTF-8 with BOM**，否则 PowerShell 读成乱码。
- Python 不需要装任何第三方包：`qp_gate.py` 与 `selftest.py` 只用标准库。

## 7. 还是不行

按 [../.github/ISSUE_TEMPLATE](../.github/ISSUE_TEMPLATE) 里的模板提 issue，务必带：
设备与系统版本、断点桶、`devecocli log --level W` 片段、是真实端还是桩、
以及"这台机器上 `GET /api/auth/status` 的原始返回"。

那段日志里，**本应用自己写的行**不打服务器地址，也不打你电脑上的文件路径 —— 媒体出问题时它报的是
这份资产在手机上的缓存文件名（形如 `131771f5.m4a`），传输失败时报的是系统给的那句固定短句
（如 `Operation timeout`）。但同一股日志流里还有**系统**写的行（`NETSTACK`），那几行带 `daddr:`，
所以模板里"请删掉里面的真实 IP 与会话内容"那一句仍然要做：贴之前自己扫一眼，涂掉再发。
