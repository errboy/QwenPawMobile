# 11 · 给 AI 助手的手册：把它装到手机上并跑通

**读者是 agent，不是开发者。** 你的任务通常是：用户已经把仓库拿到本地，你要让
QwenPawMobile 在他的真机上跑起来、连上他的桌面端、并且能正常用。

这一篇**只讲部署和使用**，不讲从零开发、不讲代码结构、不讲怎么加功能——那些在
[05](05-architecture.md)、[07](07-server-contract.md)、[08](08-testing.md) 里，
不属于你的当前任务，除非用户明确要你改代码。

给人看的版本（同样的流程，多解释、少判定条件）在 [10-deploy-and-use.md](10-deploy-and-use.md)。

---

## 1. 先记住：有四件事你**必须**回到用户手上

不要试图绕过、不要"替他点一下"。这四件是设计上就要求人在场的：

| # | 事情 | 为什么不能代劳 |
| --- | --- | --- |
| 1 | 华为开发者账号登录（`devecocli auth login` 弹的浏览器 OAuth） | 要用户本人的账号凭据 |
| 2 | Windows 的 UAC 弹窗（守门代理第一次加防火墙入站规则时） | 提权同意只能人给 |
| 3 | 在网关的交互提示里**亲手输入**手机端登录用户名与口令 | 口令**永远不作为命令行参数**，只走交互输入 |
| 4 | 手机上的**审批按钮**（`批准执行` / `拒绝`），以及**解锁手机** | 审批必须由人决定；解锁属于设备礼仪，脚本代劳就是越界 |

除这四件以外，构建、装机、起网关、驱动 UI、看日志、截图取证，你都可以自己跑。

需要用户做上面任何一件时，**清楚告诉他"现在停下，请你点一下 X"**，并且把要他敲的那一行
**写成可以直接整行粘贴的形式**（绝对路径、单条命令，不要"先 cd 再执行"）。

## 2. 前置检查（30 秒，能省你半小时）

按顺序确认，任何一条不成立就先回去问用户，别硬试：

1. `devecocli --version` 有输出吗？没有 = 用户只有 DevEco Studio 没配 CLI →
   改用 Studio 菜单等价操作，或让用户装 CLI。
2. `devecocli device list` 里**有没有目标真机**？多台设备时所有设备类命令**必须**带
   `--device <序列号>`，否则 CLI 直接报"多设备"错误。
3. 用户的 QwenPaw 桌面端**在跑吗**？（手机连的是它，它不在跑后面全白做。）
4. 手机和电脑**同网段**吗？手机走移动数据 / 访客 Wi-Fi = 一定连不上。

## 3. 部署 runbook（每步都带"成功判据"）

工作目录一律是工程根（下面用 `<root>` 指代，替换成用户的真实绝对路径）。

| 步 | 命令（单行，可整行粘贴） | 成功判据 | 失败时 |
| --- | --- | --- | --- |
| 3.1 语法闸门 | `cd /d <root> && devecocli check arkts` | 无 error | 别改代码，先把报错原文给用户 |
| 3.2 构建 | `cd /d <root> && devecocli build` | 产出 `.hap` | 见 [09 §1](09-troubleshooting.md) |
| 3.3 签名 | 先确认 `AppScope/app.json5` 的 `bundleName` 是**用户自己的**（见下）→ `cd /d <root> && devecocli auth login` → `devecocli signature generate` | `~/.ohos/config/` 下有 p12/cer/p7b | **第 1 件人来做的事**：浏览器 OAuth 让用户点 |
| 3.4 装机 | `cd /d <root> && devecocli run --device <序列号>` | 输出里有 `Smoke: PASS` | 见下面"两个必然撞上的坎" |
| 3.5 起网关 | `<root>\tools\qp-gate\start.bat` | 窗口打出 `手机填: http://<局域网IP>:61700` | 见 §5 排障表 |
| 3.6 验网关 | `<root>\tools\qp-gate\start.bat discover` | 一次回答"上游端口是几 + reachable true/false" | `reachable:false` = 桌面端没跑或端口发现失败 |
| 3.7 手机登录 | 登录配置里**端口填 61700** → 扫描 → 选中 → 填账号口令 → 登录 | 主页顶部出现 `服务器: http://…:61700` | 口令是**第 3 件人来做的事**；地址你自己能读横幅拿到 |
| 3.8 端到端确认 | 手机上发一句话，看流式回复；电脑上发起一轮，看手机是否**不退出重进**就能看到 | 两边都能看到对方 | 见 §5 |

**3.4 两个必然撞上的坎**（都是预期行为，不是工程坏了）：

- `Error Code:10106102 ... device screen is locked` → 包**已经装上了**，只是启动被锁屏挡。
  **不要自己去解锁手机**（第 4 件人来做的事）。告诉用户"手机亮屏解锁一下"，
  然后 `cd /d <root> && devecocli run --device <序列号> --skip-build`。
- 签名不一致装不上 → `cd /d <root> && devecocli run --device <序列号> --uninstall`。

**`Smoke: FAIL_CRASH` / `FAIL_BLANK`** 会把崩溃日志路径 / 截图路径直接打在输出里。
先读那个文件，再决定要不要动代码。取证命令：

```bat
cd /d <root> && devecocli log --crash --bundle-name com.liaocaosix.qwenpawmobile
```

正式版（user 版）系统会裁掉 INFO 级日志，**别因为"一条 INFO 都没有"就判断进程没起来**：

```bat
cd /d <root> && devecocli log --device <序列号> --level W --bundle-name com.liaocaosix.qwenpawmobile --tail 200
```

要把这段贴到 issue 或聊天窗口里之前先扫一眼：本应用自己写的行不带服务器地址、也不带用户电脑上的文件路径
（媒体只报手机上的缓存文件名），但同一股日志流里**系统**写的 `NETSTACK` 行带 `daddr:` —— 涂掉再发，
也不要替用户把没涂过的原文转发出去。

## 4. 你自己不改配置也能判断状态

| 想知道 | 用什么 | 注意 |
| --- | --- | --- |
| 网关活着吗、指向哪个上游 | `<root>\tools\qp-gate\start.bat discover` | 只读，安全 |
| 当前生效配置与手机该填什么地址 | `<root>\tools\qp-gate\start.bat show` | 只读，安全 |
| 网关逻辑有没有坏 | `<root>\tools\qp-gate\start.bat check` | **跑的是自带桩上游**，不和真实网关抢 61700，可放心跑；但它过了**不等于**联调过了 |
| 改端口/网段/口令 | `<root>\tools\qp-gate\start.bat config` | **每一项默认就是当前值**，一路回车 = 什么都没改。**必须用户在键盘上敲**（口令只走交互输入）。改端口会追加一次防火墙放行 → **第 2 件人来做的事（UAC）** |
| 网关是不是已经在跑 | `netstat -ano | findstr :61700` 拿 PID，再看进程命令行 | 报 `OSError [Errno 10048] bind 0.0.0.0:61700` **多半不是故障，是已经有一个实例在跑**。别急着重启，更别换端口绕开——两个网关会抢上游发现 |
| 停止网关 | 优先用它自己窗口的 Ctrl+C；**进程是脱离窗口起的（后台/脚本拉起）时只能按 PID 停**：`netstat -ano \| findstr :61700` 取 PID → `taskkill /PID <pid> /F` | 两种停法**都不删防火墙规则**（下面两行）。按 PID 停之前一定先看那一列的进程命令行，确认那是 `qp_gate.py` 而不是恰好同端口的别的东西 |
| 放行口子还在不在 | `netsh advfirewall firewall show rule name=qp-gate` | 只读。**Ctrl+C 和 taskkill 都不删规则**，重启后还在。但**没有监听者的规则是死的**：端口上没人 accept，局域网打进来只是连不上。所以查暴露面要 `netstat` 看 `LISTENING`，`show rule` 只用来查"以后还会不会自动通" |
| 收回放行口子 | `<root>\tools\qp-gate\start.bat firewall-remove` | 按规则名 `qp-gate` 整体删（它加过的端口一次全清）。要 UAC → **人来点**。删完再 `show rule` 确认没了 |

**`upstream_port` 保持 `0`（自动发现）是最佳默认**，不要为了"看起来更稳"去钉死端口：
桌面端每次重启都换随机端口，钉死之后它一重启就断，症状还长得像网关坏了。

## 5. 现象 → 动作

| 现象 | 真实原因 | 你的动作 |
| --- | --- | --- |
| 构建成功但只有 `entry-default-unsigned.hap` | 没有签名材料（预期） | 走 3.3，让用户登录华为账号 |
| `hvigor ERROR 00303116: storePassword ... less than 32` | `build-profile.json5` 里留着空串口令 | 见 [09 §1](09-troubleshooting.md)，**不要**把口令写进 `build-profile.json5` |
| 网关自己访问 `http://127.0.0.1:61700/api/auth/status` 返回 403 | **设计如此**：网关拒绝回环来源，`allow_cidrs` 不含 `127.0.0.1` | 自检走宿主机的**局域网地址**，别拿回环地址判断死活 |
| 手机上"扫描局域网"列表空 | 扫描默认端口 8088，网关在 61700；或根本不同网段；或网关没跑 | 依次：`start.bat discover` → 让用户在「登录配置」把端口填 61700 → 核对 Wi-Fi 同网段 |
| **模拟器**怎么都连不上宿主 | 模拟器看宿主要用保留地址 `10.0.2.2`，**不是** `127.0.0.1` 也不是宿主的局域网 IP；且局域网扫描在模拟器上扫的是 `10.0.2.x`，**必然扫不到** | 模拟器上要连宿主的桌面端，登录配置里**手填** `http://10.0.2.2:61700`。别把"扫描没结果"当 bug 报 |
| 登录后立刻 401 / 什么都 403 | 令牌被网关拒（口令换过、`allow_cidrs` 变了），或 `/api/auth/status` 没被网关覆盖成 `enabled:true` | 重新登录一次；仍不行跑 `start.bat check` 验网关逻辑 |
| 流式回复卡住不结束 | 中间有人换了别的转发方式，`Connection` 头被吞 | 只允许 qp-gate 这条链路；`netsh portproxy` **禁止使用**（它把来源伪装成回环，等于把鉴权绕没） |
| 图片能看、视频放不出来 | 系统 `Video` 组件加不上 `Authorization` 头，经网关时这条路径可能不可达 | **已知边界**，写进汇报里，不要当回归失败 |
| 录音总是"录音是空的，没有附上文件" | **模拟器**且宿主机没有麦克风输入设备 | 不是代码缺陷。要验声效必须真机或给电脑接输入设备 |
| `ui layout` 里找不到某个按钮 | 布局树只含**屏幕内**节点 | 先 `devecocli ui dircfling up --device <序列号>` 滚到位再 dump |
| 横屏没变化 | 手机模拟器 `emulator rotate` 是空操作 | 真机物理转，或换大屏形态验分桶 |

## 6. 驱动 UI 取证（截图 + 可点节点）

```bat
cd /d <root> && devecocli ui layout --device <序列号> --mode simplified
cd /d <root> && devecocli ui click --device <序列号> --id <节点id>
cd /d <root> && devecocli ui screenshot --device <序列号> --path <root>\shots\home.png
```

**驱动真机前先看一眼 `ui layout` 的输出**：如果里面露出用户的私人 app、相册内容、
通知正文，**立刻停止驱动真机**，改成截图取证并请用户手点。这是设备礼仪红线。

界面上的文案都是固定的（在 `l10n/Copy.ets`，页面里没有硬编码中文），你按这些字去找节点就行：

- 登录页：`扫描局域网`、`登录配置`、`已配置的地址`、`局域网中发现`、`需登录`、每行右侧形如
  `22ms` 的延迟读数、`登录`。失败时下面那行红字只有三支：`用户名或密码错误`（401）、
  `尝试过于频繁，账号暂时锁定`（423）、其余状态码一律 `登录失败：HTTP <码> <路径>`（后半截是给人抄去
  问运维的诊断，不是没翻译完的 bug）
- 登录配置页：`端口`、`扫描端口，默认 8088`、`服务器地址列表`、`保存并返回`
- 主页：`QwenPaw 会话`、`▶ 主会话`、`继续 ›`、`新建会话`、`🔒 n 项待审批`、
  `媒体缓存 … · 未发送草稿 n 条`、`清理`、`退出`
- 聊天页：`发消息…`、`发送` / `停止` / `发送并插队`、`A` / `T`、`按住 说话` / `松开发送` /
  `松开取消`、`＋`、`×`、`🖼 相册（图片/视频）`、`📄 手机文件`、`🎵 音频`、`🎙 录一段语音`、
  `📝 长文本`、`🧩 技能 (电脑)`、`🔌 MCP (电脑)`、`📁 n`
- 技能面板（`🧩 技能 (电脑)` 点开）：`电脑端的技能`、`关闭`、每行是 `emoji 名字` +
  `/名字` + 两行简介；点一行会把 `/名字` 写进输入框并关掉面板。空列表时那一行是
  `🧩 电脑端没有可用的技能`（灰的，点不动）
- 资产面板：`定位`、`下载`、`转发`、`删除副本`、`本机 …`、`仅电脑端`。四个动作**从左到右排在
  同一排**（窄屏或大字号下换行），`删除副本` 跟在 `转发` 后面 —— 它**不贴行的右边缘**：右边缘
  那一列上面一行是 `打开 ›`，破坏性的那一个落在那儿就会被误点（这是使用者报过的真事）。看到
  四个 chip 从左排、右下角空着是**预期形状**，不是"对齐丢了"
- 清理页（主页 `清理` 点开）：标题 `清理本机数据`、右上角 `全选 / 全不选`；六行类别各带
  `n 个文件 · …`（空的是 `没有可清的`，既无勾选框也不可展开）、右侧 `▾ 逐条` / `▴ 收起`
  切换本类副本清单（副本行缩进挂在类别卡左缘竖线下、不套卡；每行两行，上面是**名字**——
  打开过的会话是原名，其余是设备上的真名 `<哈希>.<后缀>` 或 `voice-<毫秒>.m4a`，过长中间
  省略、后缀留着——下面是 `大小 · MM-DD HH:mm`）、底部按钮
  `清理所选 · n 项`（没勾时是 `未选中任何一项`，点了不响应）→ 二次确认屏 `确认清理` /
  `取消` → 回执 `已清理 n 项`。**这一道与审批同理**：模拟器上你可以自己点 `确认清理`，
  **真机上归用户点**，agent 不代按。
  回执的 n 是真删掉的个数：模拟器上系统会自己回收 `cacheDir`，所以看到「已清理 0 项」
  而页面刚才还报着文件，是回收不是失败（判据见 [08](08-testing.md) §6）。
- 文件气泡：两行 `📄 文件名` / `MD 文件 · 本机 …`（或 `仅电脑端`），右边 `查看 ›`；
  **`data:` 内联那一份例外** —— 没有 `查看 ›`，写 `📄 内嵌文件` / `未知类型 · 本机 N B`（字节随
  消息到了本机，但没有可取回的引用也没有容器后缀，取不到也交不出去），这是设计不是坏了；
  点一下会先取字节（那一行变成 `正在取字节…`），然后**系统弹一道**「"QwenPaw"想要打开"<应用>"」
  （`取消` / `允许`）—— 模拟器上你可以自己点`允许`，**真机上这道归用户点**，与审批同理不由 agent
  代按。之后由系统匹配到的应用接手，App 自己不解析文件格式。没有匹配应用时提示
  `这台手机上没有能打开它的已装应用`。文件名只显示路径最后一段，长按仍然是 `引用这个文件`。
  那一行的「本机 / 仅电脑端」是气泡上次重绘时的快照，**不是此刻的保证**（系统会回收缓存）；
  要当场读数看资产面板那一行。外部应用自己的标题栏显示缓存文件名（哈希 + 真后缀），
  **不是**电脑端给的原名，这是已知外观问题，不是回归失败。
- 工具卡与"电脑端发来的文件"：一张 `🔧 工具名 · 输出` 默认收成一行的标题，点标题才展开；
  连续两张以上并成 `🔧 工具卡 ×N ▾ 看详情`。**例外**：那张卡的 `output` 若真带了文件
  （发文件工具，桩里发 `发文件` 造得出），它**不进组**、单独一行，并且卡片**上方**直接长出
  文件行（图 / 带播控的视频 / 语音 / 两行文档卡），卡片正文是工具自己那句话而不是那串 JSON。
  判据**只看形状**（`output` 里有没有带 `source` 的 `data` 块，`name` 不保证在），所以真实端那些
  `view_image` / `view_video` 的输出也会各带一行 —— 同一种形状，不是重复渲染。**真机 + 真实端
  已复验**：那两条会话里 `view_image` / `view_video` 各带一行、都不进组，非交付的卡仍并成 `×N`。
  **要不要给交付加工具白名单**这一条也于 2026-10-07 由使用者定为**不加**：只看形状换来的正是
  "桌面端新增任何回文件的工具，手机自动看得见"，而白名单会把漏掉的交付变成**静默无提示**的
  —— 那一类故障最初就是"找遍了所有工具卡才找到"。那份工具注册表归桌面端，本项目不维护它。
  多画那一行的代价是可看性而不是错误陈述：它确实是电脑端送来 / 读过的媒体，卡片可点开。
  **这是预期形状** —— 看到"工具卡上面有一张图"不是重复渲染，看到某轮工具卡没有 `×N` 组头
  也可能是这一轮真交出了文件。同一份文件会同时进顶栏 `📁` 计数与资产面板；内联（`data:`）
  那一份照旧只画在气泡里、不进面板，工具没给它名字的读成 `内嵌文件`（**不是**一串 base64）。
  **带文档的那张卡以文件名当标题**（`📁 测试1.txt`，主色加粗），工具名在标题下面一行照旧显示；
  交付那几行（文档 / 语音）走主色底与描边，与黄底折卡、灰底思考行三分。**这是预期形状**：
  一排 `🔧 send_file_to_user` 长得不一样、颜色跳出来，是"让用户滚屏幕时一眼停住"的既定目标，
  不是样式漂移；只带图/影/音的卡标题仍是 `🔧 工具名` —— 解析层只把 `name` 写进文档那一个槽位，
  图 / 影 / 音三个槽只留 ref，所以那三类卡**没有**文件名可写（顶栏 `📁` 面板那几行读得到名字，
  别据此以为卡片也该有）。**真机 + 真实端已复验**这一分支：一轮里同时交出 png / wav / mp4 时，
  三张卡各带一行媒体、都不进组、标题都是工具名 —— 那不是"改名没生效"。
- 超长引用：长按一条超过 600 字的气泡 → `引用这段文字`，输入框里是**整行收尾**的开头 +
  一行 `（这段太长，上面只是开头；完整原文随这条消息以 quote-<时间戳>.txt 发出，共 N 字）`，
  托盘同时多出一枚 `quote-….txt ×`。**这是预期形状**，不是"引用被截断"的回归；短的那条
  只贴 `> …`，托盘**不该**多出 chip。发出去后 mock/真实端收到的应该是一份 `text/plain`
  的 file part，字节数等于原文的 UTF-8 长度（不是 600）。
  **那行说明与 chip 是一对**：点掉 chip 它就没了，退出会话再进来时草稿里也没有它 ——
  这两种都是**对的**，别当成"引用丢了"去改代码；反过来，如果屏上还有这句话而托盘是空的，
  那才是 bug。
- `未送达`：一条被服务器**当场拒收**的发送（409 / 429 / 5xx）会留在屏幕上，气泡下面一行红字
  `未送达`，另有一句 `这条没有发到服务器，长按它可以引用重发`。**这是预期形状**，不是"气泡重复"
  或"该删的没删"的回归：服务器没有这句话，历史里也就没有它，重建时是**特意**留下它的。
  复现办法：桩上 `GET /__fail?codes=409` 装填一次，再发一条（见 [08](08-testing.md) §6）。
  它**不落草稿**，退出会话再进来就和那条文字一起消失 —— 别按"持久化"去测它，也不要为它加持久化：
  服务器不认的东西存本地会造出第二份真相。
- 横幅 `无法连接服务器` 而电脑端明明活着：先看 `devecocli log --level W` 里有没有
  `轮询失败：<端点> 返回的不是一份列表`。有 → 是**响应形状**问题（200 回了对象而不是数组），
  不是网络问题；这一类现在既不杀进程、也不清空列表（保留上一次的好快照），要修的是服务端那个端点。
- 表格：回复里出现"| 表头 | 表头 |"+分隔行时，气泡里是**等宽网格**（表头加粗带底色，
  每列按分隔行写的 `:` 左/中/右对齐），流式过程中光标落在**最后一格**。句子里的 `a | b`、
  七列以上的宽表**故意**渲染成普通文字（判据见 [05](05-architecture.md)「气泡里的 markdown」），
  那不是回归。带表的那条气泡会比同屏其他气泡宽（它吃满自己的宽度上限才能分列），
  旁边没有表的气泡仍按内容收缩 —— 两者都是对的。
- 审批卡片：`任务已暂停，等待你的决定`、**`批准执行`**、**`拒绝`** ← 这两个只能人点

输入框上方那排选择器最多三枚（循环模式 / 模型 / 审批），**前两枚只在电脑端真的有可选项时才渲染**
——芯片上写的是**当前选中的名字 + `▾`**，不会写「循环模式」「审批」这种类别词。审批那枚永远在，
默认读数形如 `电脑端默认 ▾`（五个取值：`电脑端默认` / `严格模式` / `智能模式` / `自动模式` /
`关闭模式`）。真实桌面端上常常只有这一枚。看不到别的芯片不等于回归失败，别为此去改代码。

## 7. 红线（做了就是事故，不是风格问题）

- **绝不提交**：`tools/qp-gate/gate.json`、`external-signing-config.json`、
  `local.properties`、`scratch/**`、`screenshots/**`、
  `oh_modules/`、`.hvigor/`、`**/build/`。
- **仓库里的任何文件都不能出现**：用户真实的局域网 IP、真实的桌面端随机端口、
  真机调试地址、账号用户名、任何绝对个人路径。截图/布局 dump 里带了，就**不要**把它
  `git add` 进去（这条栽过一次：一个 `ui layout` 的 json 里存了真实服务器地址）。
- **口令不进命令行参数、不进日志、不进任何文件**。网关的口令只能在交互提示里由用户输入。
- **不替用户点审批**，不实现自动批准 / 超时默认同意 / "本次都同意"。
- **不写桌面端的全局配置**：`/workspace/running-config`、`/settings/upload-limit`、
  MCP 的开关与工具白名单、技能的启用状态，全部**只读**（PUT 是整文档替换，误点一次就把
  用户桌面端改了）。
- **不 `git push`**，不改 git config，不 `git add -A`。用户没明确说推，就只本地提交。
- **不用 `netsh interface portproxy`**，**不改桌面端源码去绑 `0.0.0.0`**（安装版是
  PyInstaller 编译包，改了无效，而且一升级就没了；这条路已经有 qp-gate 替代）。
- **不解锁用户手机**、不在用户手机上删数据、不点系统弹窗里"允许"之外的东西。

## 8. 汇报口径（用户会拿本机数据核对，这条很重要）

1. **标明每一步测的是桩还是真实端**。`start.bat check` / mock 服务端跑出来的绿，
   **不等于**联调通过。用户拿真桌面端的数据核对，一次混报就把后面所有结论都废了。
2. **没在设备上亲眼见过的，一律写"未验证"**，不要用"应该可以""理论上"。
3. 报告结构建议：已做（带证据：命令 + 关键输出行）/ 未验证（带为什么）/
   需要人做的（带可直接粘贴的单行命令）。
4. 交付物（截图、录屏、日志）要自带标注说明它是模拟器还是真机、桩还是真实端。

## 9. 你被要求改代码时

这一篇帮不上忙，去读工程根的 `AGENTS.md`（ArkTS 禁 `any`、文案必须进 `l10n/Copy.ets`、
日志走 `core/Log.ets`、依赖方向 `pages → ui → state → api → net → core`），
以及 [05](05-architecture.md) / [07](07-server-contract.md) / [08](08-testing.md)。
交付前四连：`devecocli check arkts` → `devecocli check lint` → `devecocli build` →
**至少在一个设备形态上真看过**，再加 CHANGELOG 一行。
动过被文档引用的那些行（搬函数、加注释、删代码）之后再加一条：`python tools/doc_line_check.py`，
0 problems 才算文档没有说谎。同一条命令也会报**断掉的相对链接**（新写文档时加的那些），
所以改了文件名或挪了 docs 里的文件也要跑它。它还比对**每个 `Copy.fill*` 调用点填的占位符数量**：
`String.replace('%s', x)` 只换第一个，模板多写一个 `%s` 或调用点少填一个参数，屏幕上就是一行
光秃秃的 `%s`，而 ArkTS 与 lint 两处都不报。
